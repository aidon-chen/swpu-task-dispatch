# PRD · 值班表导入

> 版本：v2.0（2026-08-26 用户拍板：方案 D + 值班表页内导入，仅视觉中心主任）
> 数据源：`大学生全媒体中心2025-2026学年春季学期值班表.xlsx`（项目根目录）
> 关联：`cloudfunctions/getDutySchedule/`、`pages/duty-schedule/`

## 1. 概述

### 1.1 背景与痛点
- 值班表页面（duty-schedule）目前**只有成员状态矩阵（available/busy/unavailable），没有真实值班安排数据**——`duty_schedule` 集合为空，页面只能看到成员列表，看不到"谁在什么时候值班"。
- 中心有一份真实的《大学生全媒体中心2025-2026学年春季学期值班表.xlsx》，记录了每周一至周五各时段各团队的值班人员，目前**只存在于 Excel，没有进入小程序**。

### 1.2 数据源真实结构（已探明，2026-08-26）
| 维度 | 结构 |
| --- | --- |
| Sheet | 5 个：`星期一`~`星期五`（每个 sheet 是一天的值班安排） |
| 第 1 行 | 标题「大学生全媒体中心值班表（周X）」 |
| 第 2 行 | 表头：`时间 ｜ 微信团队(B) ｜ 微博团队(C) ｜ 视觉中心(D) ｜ 采访组(E) ｜ 职能中心(F) ｜ 后台(G) ｜ 学习强国(H)`（I 列为附加备注如「打扫卫生」） |
| A 列（时段） | `1-2节 8：00-9:35` / `3-4节 9:50-11:25` / `6-7节 14:30-16:05` / `8-9节 16:30-17:55` |
| 数据格 | 值班人名，多人以「、」或「，」分隔；可能存在重复名；个别格为非人名（如「打扫卫生」） |

**核心事实：该表是「周几 × 时段」的固定周模板，不包含具体日期。** 它描述的是"每周一第 1-2 节视觉中心蔡江豪、李可欣值班"这类循环安排。

### 1.3 与现有数据模型的冲突（必须解决）
- `duty_schedule` 现有模型：`{ userId, date:'YYYY-MM-DD', status:'available'|'busy'|'unavailable' }`——**粒度是「人 × 具体日期」，无时段维度，一天一条状态**。
- 值班表：**粒度是「人 × 周几 × 时段」**，一天可能有多个时段多人值班。
- 直接硬塞（把当天值班的人标 `busy`）会丢失时段信息，且语义混淆（`busy` 本意是成员手头有事，非"在值班"）。

## 2. 目标与非目标

- **目标**：① 把 xlsx 的周值班模板完整导入云端；② 值班表页面能展示"本周值班安排"（周几 × 时段 × 团队/人）；③ 导入幂等可重跑；④ 与现有成员状态矩阵共存不冲突。
- **非目标**：不做按具体日期的排班（如调休/节假日特殊排班）；不做值班提醒推送；不改造 `user_status` 出勤状态逻辑；不导入非视觉中心团队的人员账号（仅展示团队名，不要求 users 有对应账号）。

## 3. 方案对比与选型（v2.0：已拍板方案 D）

| 方案 | 做法 | 优点 | 缺点 | 结论 |
| --- | --- | --- | --- | --- |
| A. 塞进 duty_schedule | 展开成日期标 busy | 改动最小 | 丢时段；busy 语义混淆 | ❌ |
| B. 扩展 duty_schedule 加 slot | 并入现有集合 | 单一集合 | 动现有矩阵/页面/接口三处，语义仍混 | ⚠️ |
| C. 周模板集合 | 只存 weekday×slot×人 | 最简（~60 条） | **回答不了"今天谁值班"**；调休无法按天改 | ⚠️ |
| **D. 展开成具体日期（已选）** | **周模板按学期校历展开 → duty_records（date×slot×人，一人一条）** | **「今天/某天谁值班」直接可查；调休按天改；与 getDutySchedule 的 date 查询对齐；导入一次性脚本转换** | 需学期日期范围参数；记录约 800~900 条（无压力） | ✅ **采用** |

> 选型依据：值班表最常被问的是「今天/某天谁值班」，只有按具体日期建模才能回答；运营上请假/调休都是按天修改；学期范围参数一次配置即可。
> 学期范围：2025-2026 春季 = 2026-02-23（周一）~ 2026-06-30，周一~周五展开（节假日排除可后续按参数配置）。

## 4. 功能点拆分（核心/辅助）

| ID | 功能点 | 类型 | 说明 | 验收标准（AC） |
| --- | --- | --- | --- | --- |
| P1 | xlsx 解析 + 日期展开 | 核心 | Python 脚本：5 sheet→weekday、A 列→slot、团队列→人名；顿号/逗号分隔、去重、过滤非人名；按学期校历展开成具体日期 → 生成 `duty_data.json` | AC1：解析完整；AC2：去重/过滤正确；AC3：展开后每条含 date/weekday/slot/team/name |

| P5 | 清理入口 | 辅助 | 提供清空 duty_records 能力（重导前清空） | AC1：清空后为空，不影响 duty_schedule |

## 5. 数据结构

### 5.1 新集合 `duty_records`
```js
{
  date: 'YYYY-MM-DD',      // 具体值班日期（已按学期展开）
  weekday: 1-5,            // 1=周一 … 5=周五（冗余便于分组展示）
  slot: '1-2节',           // 时段标签（'1-2节'|'3-4节'|'6-7节'|'8-9节'）
  team: '视觉中心',         // 团队（微信/微博/视觉中心/采访组/职能中心/后台/学习强国）
  name: '蔡江豪',           // 值班人姓名（一人一条）
  source: '2025-2026春季',  // 学期标识
  createdAt: Date,
  updatedAt: Date
}
```
- **唯一键**：`date + slot + name`（幂等 upsert 依据）。
- 一人一条：便于按人查询与未来"我的值班"；页面按 weekday/slot 分组渲染。
- 不强关联 users._id（值班人可能未注册，姓名匹配账号为后续增强）。

### 5.2 解析与展开规则（P1）
1. sheet 名 → `weekday`（星期一=1 … 星期五=5）。
2. A 列取值 → `slot`（取 `^(\d+-\d+节)` 前缀，无法识别该行跳过并记日志）。
3. B~I 列 → `team` 取第 2 行表头；数据格按 `[、，,，]` 分隔 → 每人一条。
4. 过滤：空白跳过；**非人名黑名单**（`打扫卫生` 等）跳过；**重复名去重**。
5. **展开**：学期范围（`2026-02-23` ~ `2026-06-30`）内每周一~周五，按 weekday 匹配当天时段排班，生成具体日期记录。
6. 清洗：全角符号按分隔处理、trim。

## 6. 接口

| 云函数 | 入参 | 返回 |
| --- | --- | --- |
| `importDutyRecords` | 无（数据随包 `duty_data.json`）；`{ action?: 'import'|'clean' }` | import：`{ inserted, updated, skipped, total }`；clean：`{ removed }` |
| `getDutyRecords` | `{ weekday?: 1-5, date?: 'YYYY-MM-DD', team?, source? }` | `{ list: [{date, weekday, slot, team, name}] }` |

- `importDutyRecords` 权限：**仅视觉中心主任（center_director）**，含测试模式调试角色信任（testConfig 门禁）；clean 同权限。
- 幂等：按 `date+slot+name` 查重，存在则 update（刷新 updatedAt），不存在则 add。
- `getDutyRecords` 供值班表页「本周值班」区块按 weekday 分组渲染（前端取本周的 weekday 列表或按 date 范围查）。

## 7. 边界与异常

| 场景 | 处理 |
| --- | --- |
| 同格重复名（如「张欣颖、周之画、张欣颖」） | 去重，一人一条 |
| 两种分隔符混用（「倪文璇，李沛轩」） | 统一按分隔符切分 |
| 非人名单元格（「打扫卫生」「值班地点」） | 黑名单过滤 |
| 表头行/标题行混入数据 | 按固定行位（第 2 行表头、A 列时段）解析，非固定行忽略 |
| 记录数超限 | records ≤ 500，超限返回 paramError |
| 同一人跨团队出现（如视觉中心+学习强国） | 按 team 维度分别存（不合并），展示按团队分组 |
| 学期切换（下学期的表） | `semester` 字段区分；清空旧学期或按 semester 过滤 |
| 姓名与 users 不匹配 | 本期不绑定 `_id`，仅文本展示；后续可做姓名→账号匹配增强 |
