# 任务派发系统 · 文档中心

> 西南石油大学视觉中心（摄影部 + 视频部）的微信小程序任务派发系统。本文档是整套技术文档的入口与导航。

**一句话说明**：这是一个面向约 40 人学生团队的微信小程序，用于任务派发、人员状态管理、值班表、机位管理和统计报表。前端为微信小程序原生框架（含 TDesign 组件库），后端为微信云开发（CloudBase）。

---

## 这套文档解决什么问题

之前只有「设计态」文档（PRD、架构设计、图表），新人接手项目时找不到：怎么把项目跑起来、接口到底怎么调、哪些功能其实还没写完。本体系把文档按**开发者实际阅读路径**重新组织，并明确标注每个功能的**真实落地状态**。

### 状态图例

文档中每个功能/接口都会带一个状态标记，避免你照着文档跑出预期之外的结果：

| 标记 | 含义 |
|------|------|
| ✅ 已实现 | 代码已落地，文档照真实代码编写 |
| 🟡 部分实现 | 核心逻辑在，但有关键缺口（文档会写明缺口） |
| ⚠️ 规划中（未实现） | 设计文档里有，但后端/前端尚未落地 |

> ⚠️ **重要提醒**：本项目的设计与实现存在偏差。例如架构设计文档写的是「小程序内通知」，但 `sendNotification` 云函数实际用的是微信订阅消息且模板 ID 还是占位符；错误码设计是 5 位（1001/2001…），但云函数实际只返回 `0/1/2/3`。所有这类偏差，本文档体系以**代码真实状态**为准，并在对应位置标注。

## 如何参与文档建设

文档和代码一样，是项目资产：

1. 所有文档放在 `docs/` 下，随代码版本控制。
2. 改功能时**同步改文档**（尤其是 API 参考），代码没有文档等于没完成。
3. 发现文档与代码不符，**先改文档**（以代码为准），并在 PR 里说明。
4. 新增「规划中」功能落地后，把对应标记从 ⚠️ 改为 ✅。

文档规范与贡献指南详见 `05-规范与贡献/`（规划中）。
