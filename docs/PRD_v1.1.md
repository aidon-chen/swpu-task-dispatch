# 任务派发系统产品需求文档（PRD）

## 1. 项目信息

**项目名称**: task_dispatch_miniprogram  
**项目类型**: 微信小程序  
**目标用户**: 约40人（摄影部 + 视频部）  
**技术栈**: 微信小程序原生开发 + 云开发（推荐）  
**文档版本**: v1.4  
**更新日期**: 2026年6月（架构审查修订：快捷模式纯展示、通知改小程序内、导出改剪切板）

**原始需求概述**:
开发一个面向学校视觉中心的任务派发系统，支持摄影部和视频部两个部门的工作任务分配、人员管理、值班安排和拍摄机位管理。

**新增需求概述**:
- 统计报表功能：统计成员参与次数，支持按月/按学期查看，方便稿分填写
- 新闻网自动匹配功能：自动匹配任务与学校新闻报道，提供稿分证明链接
- 随机选人工具：管理人员界面内置随机选人，方便公平分配任务

> **注意**: 以下需求由用户最终确认：
> - 权限密钥：一次性使用，一个密钥对应一个用户
> - 任务提醒：任务开始前2小时，小程序内通知（notifications集合+红点）
> - 不可用状态：成员因上课/生病/外出等原因标记为不可用，需附文字说明+图片（可选）
> - 成果交付：默认标记完成，需要调整由普通成员申请 + 管理人员操作，或管理人员直接操作
> - 跨部门协作：存在摄影部和视频部协作任务
> - 学期统计：支持按学期统计
> - 新闻匹配：中文分词+加权评分机制（jieba分词，标题60%+正文40%）
> - 多个新闻：直接罗列显示
> - 新闻链接：使用WebView内嵌打开
> - 爬虫频率：先保证功能实现，后期调整
> - 创建任务双模式：快捷模式（展示图片/文字原内容）+ 详细模式（手动输入）
> - 任务必填项：仅任务标题 + 任务时间
> - 值班表：按课节时间段（1-2节、3-4节、6-7节、8-9节）
> - 随机选人：从活动时间段内值班的部门成员中随机抽取
> - 关联机位：选填
> - 创建任务权限：摄影部主任、视频部主任、视觉中心主任均可用
> - 通知方式：小程序内通知，不依赖微信订阅消息

## 2. 产品定义

### 2.1 产品目标

构建一个高效的移动端任务派发与协作平台，实现"任务快速分配 → 人员确认 → 成果交付"的全流程数字化管理，提升视觉中心工作效率。

**核心目标**（4个正交目标）:
1. **提升任务派发效率** - 管理人员可在3分钟内完成单次任务派发
2. **实现人员状态透明化** - 实时掌握所有成员可用状态及不可出勤原因
3. **沉淀组织资产** - 系统化记录拍摄机位、任务历史等经验知识
4. **简化稿分统计流程** - 自动生成参与统计和新闻链接，减少手工整理时间

### 2.2 用户角色与权限

| 角色 | 权限级别 | 核心职责 |
|------|---------|---------|
| 视觉中心主任 | Level 3（最高） | 全局管理、跨部门任务派发、系统配置、查看全员统计 |
| 摄影部主任 | Level 2 | 摄影部任务派发、人员管理、查看部门统计 |
| 视频部主任 | Level 2 | 视频部任务派发、人员管理、查看部门统计 |
| 普通成员（摄影） | Level 1（默认） | 接收任务、提交交付物、请假/状态上报、查看个人统计 |
| 普通成员（视频） | Level 1（默认） | 接收任务、提交交付物、请假/状态上报、查看个人统计 |

**角色升级机制**:
- 新用户注册后默认为"普通成员"
- 需输入管理员提供的"权限密钥"升级角色
- 密钥由视觉中心主任生成并分发给各部门主任
- **密钥规则**: 一次性使用，一个密钥对应一个用户，使用后立即失效

**统计报表权限**:
- 普通成员：只能查看自己的统计报表
- 摄影部主任/视频部主任：可查看本部门所有成员的统计报表
- 视觉中心主任：可查看所有成员的统计报表

### 2.3 用户故事

**视觉中心主任**:
- 作为视觉中心主任，我希望能查看所有部门的任务概况和人员状态，以便统筹全局资源
- 作为视觉中心主任，我希望能生成和管理权限密钥，以便控制角色分配
- 作为视觉中心主任，我希望能查看历史任务数据和统计报表，以便优化人员配置
- 作为视觉中心主任，我希望能查看所有成员的稿分统计，以便公正评估工作贡献

**摄影部主任**:
- 作为摄影部主任，我希望能快速创建拍摄任务并指派给部门成员，以便高效完成工作分配
- 作为摄影部主任，我希望能查看部门成员的值班表和可用状态，以便合理安排任务
- 作为摄影部主任，我希望能管理常用拍摄机位信息，以便新人快速了解拍摄要点
- 作为摄影部主任，我希望能查看部门成员的参与统计和新闻匹配情况，以便协助成员完成稿分填写

**视频部主任**:
- 作为视频部主任，我希望能快速创建视频拍摄/剪辑任务并指派给部门成员，以便高效完成工作分配
- 作为视频部主任，我希望能查看部门成员的值班表和可用状态，以便合理安排任务
- 作为视频部主任，我希望能管理视频拍摄相关的机位信息和注意事项
- 作为视频部主任，我希望能查看部门成员的参与统计和新闻匹配情况，以便协助成员完成稿分填写

**普通成员**:
- 作为普通成员，我希望能快速查看分配给我的任务详情（时间、地点、联络人），以便准时出任务
- 作为普通成员，我希望能便捷地上报我的空闲/忙碌状态，以便主任合理安排任务
- 作为普通成员，我希望能在无法出任务时上传文字/图片说明原因，以便主任理解并调整安排
- 作为普通成员，我希望能查看我的任务历史记录和交付成果，以便回顾工作
- 作为普通成员，我希望能查看我的月度/学期参与统计，以便快速填写稿分表
- 作为普通成员，我希望能自动匹配我参与任务的新闻报道链接，以便提供稿分证明

## 3. 需求池（Requirements Pool）

### P0 - 核心功能（必须有）

#### 3.1 用户认证与角色管理
- **R1**: 支持微信授权登录（获取openid、昵称、头像）
- **R2**: 新用户注册后默认角色为"普通成员"，需选择部门（摄影部/视频部）
- **R3**: 支持通过"权限密钥"升级角色（摄影部主任、视频部主任、视觉中心主任）
- **R4**: 密钥验证机制：密钥一次性使用，一个密钥对应一个用户，使用后立即失效
- **R5**: 用户可查看自己的角色和权限说明

#### 3.2 任务派发核心流程
- **R6**: 主任可创建任务，支持双模式：
  - **快捷模式**：上传图片（如活动通知截图）或粘贴文字（如微信群通知），直接展示原始内容 [✏️ v1.4]
  - **详细模式**：手动输入，必填仅2项（任务标题、任务时间），其余为选填
  - 任务字段：标题(必填)、时间(必填)、地点(选填)、联络人(选填)、类型(选填)、描述(选填)、关联机位(选填)、指派人员
- **R7**: 任务创建后，被指派成员在小程序内收到通知 [✏️ v1.4]
  - 通知入口：首页 TabBar 红点 + 个人中心"消息中心"
  - 提醒时机：任务开始前2小时自动推送（由定时触发器 scheduleNotify 扫描）
- **R8**: 被指派成员可在小程序内查看任务详情
- **R9**: 主任可编辑/取消已创建的任务（任务开始前）
- **R10**: 支持任务优先级标识（普通/紧急）

#### 3.2.1 随机选人工具 🆕
- **R53**: 管理人员界面内置随机选人工具
  - 在任务创建页面的"指派人员"区域，提供"随机从值班表抽取"按钮
  - 根据活动时间段（课节），从该时段值班的部门成员中随机抽取（仅抽取可用状态成员）
  - 支持指定抽取人数（如随机选2人）
  - 随机结果可手动调整（增加/删除）
  - 确保公平分配，降低主管选择压力

#### 3.3 人员状态管理
- **R11**: 普通成员可设置自己的状态：
  - 可用（空闲）
  - 忙碌（已安排任务）
  - 不可用（需说明原因，如上课/生病/外出）
- **R12**: 成员选择"不可用"时，必须上传原因说明（文字必填，图片选填）
- **R13**: 主任可查看部门所有成员的状态列表
- **R14**: 主任可查看成员"不可用"的具体原因（文字+图片）

#### 3.4 值班表/可用性日历（参考大学生全媒体中心值班表格式）
- **R15**: 成员可设置自己的每周课节值班时间段
  - 时间段格式：1-2节(8:00-9:35)、3-4节(9:50-11:25)、6-7节(14:30-16:05)、8-9节(16:30-17:55)
  - 值班地点：成都校区思学楼CD205
  - 按周查看：周一至周五，每天4个课节时段
- **R16**: 成员可设置临时不可用时间段（如考试周、请假）
- **R17**: 主任视图：按课节+星期展示部门成员值班矩阵，标注可用/不可用状态
- **R18**: 值班表支持按周/按天切换查看，不可用成员以红色标注且显示原因

### P1 - 重要功能（应该有）

#### 3.5 任务确认与交付
- **R19**: 被指派成员可"确认接受"或"申请调整"任务
- **R20**: 任务完成后，**默认自动标记为完成**
- **R21**: 成员可申请调整交付状态（需主任审批）
- **R22**: 主任可直接修改交付状态（确认或退回重做）

#### 3.6 拍摄机位管理
- **R23**: 主任可添加/编辑/删除常用拍摄机位信息，包含：
  - 机位名称
  - 位置描述
  - 注意事项（文字）
  - 参考图片（可选）
  - 适用任务类型标签
- **R24**: 所有用户可查看机位列表和详情
- **R25**: 创建任务时，可关联常用机位（选填）

#### 3.7.1 双模式创建任务 🆕 [✏️ v1.4]
- **R54**: 创建任务页面支持快捷/详细两种模式切换
  - **快捷模式**：上传图片或粘贴文字，直接展示原始内容（不对图片/文字做自动提取）
  - **详细模式**：手动填写表单，仅标题和时间必填
  - 两种模式可随时切换，共享同一个任务数据

#### 3.7 消息通知 [✏️ v1.4]

采用**小程序内通知**，无需用户额外授权：
- **R26**: 任务派发成功 → 写入 notifications 集合，小程序内红点提示
- **R27**: 任务时间变更 → 通知相关成员
- **R28**: 任务取消 → 通知被指派成员
- **R29**: 任务开始前2小时 → 定时触发器扫描后写入提醒通知

#### 3.8 任务列表与筛选
- **R30**: 用户可查看"我的任务"列表（按时间排序）
- **R31**: 支持按任务状态筛选（待确认/进行中/已完成/已取消）
- **R32**: 主任可查看部门任务列表和统计

#### 3.9 统计报表功能
- **R41**: 系统自动统计每个成员的参与任务次数和详细信息
  - 统计字段：任务名称、任务时间、任务地点、任务类型、完成状态
  - 支持按月份/学期/自定义时间段筛选
  - 显示汇总数据：总参与次数、各月份/学期分布
- **R42**: 普通成员可查看自己的统计报表
  - 显示图表：月度/学期参与次数图表
  - 显示列表：任务明细（时间、地点、名称）
  - 支持选择月份/学期查看历史数据
- **R43**: 主任可查看部门所有成员的统计报表
  - 成员列表视图：显示每个成员的参与次数
  - 点击成员可查看详细报表
  - 支持按月份/学期筛选
- **R44**: 视觉中心主任可查看所有部门成员的统计报表
- **R45**: 统计报表页面提供"新闻匹配"入口
  - 每个任务旁显示"匹配新闻"按钮
  - 点击后触发新闻网爬虫匹配
- **R46**: 统计报表提供一键复制纯文本功能 [✏️ v1.4]
  - 点击"导出"按钮 → 云函数生成纯文本摘要 → 调用 wx.setClipboardData() 复制到系统剪切板
  - 文本内容：姓名、部门、学期、总参与次数、任务明细列表
  - 粘贴到 WPS 表单、微信聊天等任意工具中使用
- **R47**: 为后期WPS表单自动填写预留接口
  - 数据结构设计考虑后期自动化需求
  - 提供标准化数据输出格式

### P2 - 辅助功能（最好有）

#### 3.10 新闻网自动匹配功能
- **R48**: 系统支持爬取西南石油大学新闻网（https://www.swpu.edu.cn/news/yw.htm）
  - 使用爬虫方式（无API）
  - 基础实现即可，先保证功能可用
- **R49**: 新闻匹配逻辑
  - 关键词：任务标题（使用jieba中文分词提取关键词）
  - 时间范围：任务开始时间后7天内
  - 匹配字段：新闻标题和正文
  - 匹配算法：加权评分（标题60% + 正文40%），超过阈值显示
- **R50**: 用户在统计报表页面点击某个任务时，触发新闻匹配
  - 系统自动爬取新闻网
  - 显示匹配到的新闻列表（标题 + 链接）→ **直接罗列显示**
  - 如无匹配结果，显示"未找到相关新闻"
- **R51**: 用户可点击新闻链接，使用**WebView内嵌**打开新闻页面
  - 提供"复制链接"按钮作为备选
- **R52**: 系统缓存新闻匹配结果
  - 避免重复爬取
  - 缓存有效期：30天

#### 3.11 数据统计与导出
- **R33**: 主任可查看部门任务统计（完成率、成员工作量等）
- **R34**: 支持导出任务数据（Excel格式）

#### 3.12 评价与反馈
- **R35**: 主任可对成员的任务完成情况进行评价（星级/标签）
- **R36**: 成员可对方便性、沟通等进行反馈

#### 3.13 高级搜索与过滤
- **R37**: 支持按关键词搜索任务和机位
- **R38**: 支持按时间段、人员、任务类型组合筛选

#### 3.14 模板功能
- **R39**: 主任可保存常用任务配置为模板
- **R40**: 创建任务时可选从模板快速生成

## 4. UI设计描述

- **设计语言**: 简洁、高效、信息密度适中

- 微信授权登录按钮
- 显示当前角色
- 权限密钥输入入口（一次性使用）

#### 页面2: 首页（任务概览）

- 任务类型下拉选择
- 开始/结束时间选择器
- 地点输入
- 联络人输入
- 任务描述（选填）

- 搜索框

- 机位详情页（参考图、位置描述、注意事项）

- 月份/学期切换

### 4.3 关键交互设计

1. **任务提醒**: 任务开始前2小时，小程序内自动通知（首页红点+消息中心）[✏️ v1.4]
2. **状态上报流程**: 首页→设置状态→选择状态→填写原因→上传图片（可选）→提交
3. **任务接受流程**: 收到通知→查看详情→确认接受/申请调整→填写原因（如调整）
4. **机位关联**: 创建任务时选择机位→自动填充地点字段
5. **成果交付**: 默认自动标记完成，成员可申请调整，主任可手动修改
6. **新闻匹配交互**: 点击"匹配新闻" → loading → 显示新闻列表（罗列式） → 点击以WebView打开

## 5. 技术方案建议

### 5.1 技术栈
- **前端**: 微信小程序原生框架（WXML + WXSS + JS）+ wx-charts（图表库）
- **后端**: 微信云开发（CloudBase）
  - 云函数：处理业务逻辑
  - 云数据库：存储业务数据
  - 云存储：存储图片等资源
- **推送**: 小程序内通知（notifications 集合 + 红点提示），无需微信订阅消息授权 [✏️ v1.4]
- **爬虫**: 云函数 + axios + cheerio（HTML解析） + jieba（中文分词）

### 5.2 数据库设计（核心集合）

**users 集合** (用户信息):
```
{
  _id, openid, name, department: 'photography' | 'video',
  role: 'member' | 'photo_director' | 'video_director' | 'center_director',
  avatar, createdAt, updatedAt
}
```

**tasks 集合** (任务信息):
```
{
  _id, title, type, startTime, endTime, location, contact,
  description, deliverables, assignedTo[], creatorId, status,
  priority, locationId, isCrossDepartment: boolean,
  semester, createdAt, updatedAt
}
```

**user_status 集合** (用户状态):
```
{
  _id, userId, status: 'available' | 'busy' | 'unavailable',
  reason, images[], startDate, endDate, createdAt
}
```

**locations 集合** (拍摄机位):
```
{
  _id, name, description, notes, images[], tags[],
  createdBy, createdAt, updatedAt
}
```

**keys 集合** (权限密钥):
```
{
  _id, key, role, usedBy, usedAt, isUsed: boolean,
  createdBy, createdAt
}
```

**news_cache 集合** (新闻缓存):
```
{
  _id, taskId, taskTitle,
  newsList: [{ title, url, publishDate, matchScore }],
  cachedAt, expireAt
}
```

### 5.3 关键云函数
1. `login` - 微信登录
2. `verifyKey` - 验证权限密钥（一次性）
3. `createTask` - 创建任务（支持跨部门）
4. `updateTask` - 更新任务
5. `getTasks` - 获取任务列表
6. `updateUserStatus` - 更新用户状态
7. `getDutySchedule` - 获取值班表
8. `createLocation` - 创建机位
9. `getLocations` - 获取机位列表
10. `sendNotification` - 发送通知（支持定时提醒）
11. `getReport` - 获取统计报表（支持按月/按学期）
12. `crawlNews` - 爬取新闻网并匹配任务（jieba分词+加权评分）
13. `getNewsCache` - 获取新闻缓存数据
14. `exportReport` - 导出统计数据（为WPS准备）

### 5.4 新闻爬虫技术方案

**爬虫实现**:
- 云函数 + axios + cheerio 解析HTML
- 目标网站：https://www.swpu.edu.cn/news/yw.htm
- 爬取策略：
  1. 提取任务标题 → jieba中文分词 → 获取核心关键词
  2. 爬取任务开始后7天内的新闻列表
  3. 加权评分：新闻标题匹配60% + 正文匹配40%
  4. 超过阈值（30分）则显示，否则不显示
  5. 显示格式：罗列式，点击用WebView打开

**性能优化**:
- 缓存机制：已爬取的结果缓存30天
- 限流机制：避免频繁请求（先保证功能，后期调优）
- 错误处理：页面结构变更时返回友好报错提示

**合规性考虑**:
- 遵守目标网站的robots.txt规则
- 控制爬取频率，添加礼貌性延迟
- 仅用于内部稿分统计，不对外传播

### 5.5 学期统计方案
- 学期定义：秋季学期（9月-1月）、春季学期（2月-6月）
- 支持手动配置学期起止日期
- 统计维度：按学期聚合参与次数、任务类型分布
- 与月份统计共用一个报表接口，通过type参数区分

## 6. 项目里程碑建议

### Phase 1: MVP（最小可行产品）- 4周
- 微信登录 + 角色管理（含一次性密钥的生成与验证）
- 基础任务派发功能（支持跨部门）
- 人员状态上报（含不可用原因说明）
- 小程序内消息通知（任务分配/提醒/取消/完结）
- 成果交付（默认完成机制）
- 定时触发器（scheduleNotify：提前2h提醒 + 自动完结）

- 值班表功能
- 任务确认与交付（申请调整 + 管理操作）

- 任务列表优化

- 新闻匹配与展示（加权评分 + 罗列式 + WebView）
- 数据导出（为WPS准备）

### Phase 4: 体验优化与上线 - 2周
- UI/UX优化
- 性能调优
- 爬虫频率调优
- 内测与反馈收集
- 正式上线

## 7. 风险与应对

| 风险 | 影响 | 应对措施 |
|------|------|---------|
| 微信订阅消息授权率低 | 用户可能错过任务通知 | 采用小程序内通知（无需授权），首页红点+消息中心 [✏️ v1.4] |
| 角色密钥泄露 | 未授权角色升级 | 一次性使用机制，使用后立即失效 |
| 40人并发性能问题 | 影响使用体验 | 使用云开发的自动扩容能力 |
| 用户忘记更新状态 | 主任无法准确派发任务 | 提供状态到期自动重置机制 |
| 新闻网站反爬措施 | 无法正常匹配新闻 | 添加请求头伪装、控制频率、提供手动输入备选方案 |
| 新闻匹配准确度低 | 用户需要手动查找 | jieba分词+加权评分机制提高精度 |
| 爬虫功能被封禁 | 统计报表功能受损 | 使用缓存减少请求、提供手动输入新闻链接的备选方案 |
| 新闻网页面结构变更 | 爬虫失效 | 添加报错机制，解析失败时给出友好提示 |
