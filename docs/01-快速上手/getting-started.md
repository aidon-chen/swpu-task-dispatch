# 快速上手：把项目跑起来

**目标**：从零开始，在本地微信开发者工具里把「任务派发系统」小程序编译运行起来，并成功调用云函数。预计 **15 分钟**。

**你会得到**：一个能登录、能看到任务列表、能切换环境的小程序开发环境。

> 本文基于真实仓库状态编写。项目 AppID `wx8fdb0c0acb28ee1a`，云环境 `cloud1-d8gdddel1d4b1cea1`，dev/test/prod 当前共用此环境。

## 前置准备（一次性）

开始前请确认：

- [ ] 有微信账号，且是该小程序**开发者**（在 [微信公众平台](https://mp.weixin.qq.com) → 成员管理 中已被添加）。否则无法预览/上传。
- [ ] 电脑已装 [微信开发者工具（稳定版）](https://developers.weixin.qq.com/miniprogram/dev/devtools/download.html)。建议 Stable 版，别用 RC/Nightly（云开发支持更稳）。
- [ ] 已开通**云开发**：用同一微信账号登录 [云开发控制台](https://console.cloud.tencent.com/tcb)，确认环境 `cloud1-d8gdddel1d4b1cea1` 存在。若你是新接手且环境不在你账号下，找项目负责人把环境**共享**给你，或确认你就是环境所有者。
- [ ] Node.js 已安装（用于「构建 npm」）。打开终端跑 `node -v`，有版本号即可（16+ 均可）。

> 不需要单独装 npm 包到全局。`tdesign-miniprogram` 已在项目 `package.json` 里，靠开发者工具「构建 npm」处理。

---

## 第 1 步：导入项目

打开微信开发者工具 → 右上角「导入项目」：

- **目录**：选 `miniprogram/` 文件夹（即含 `app.js` / `project.config.json` 的那一层，**不是**仓库根目录）。
- **AppID**：选「测试号」不行，要填正式 `wx8fdb0c0acb28ee1a`（下拉可选你账号下已绑定的；若没有，手动粘贴）。
- **后端服务**：选「微信云开发」。
- 勾选「使用 npm 模块」（默认勾上即可）。

点「导入」。

你应当看到模拟器加载出小程序界面。若白屏或报错，先别慌，继续往下做第 2、3 步（云环境和 npm 没就绪时首页常报错，属正常）。

> **提示**：导入目录务必是 `miniprogram/`。选错成仓库根目录会因为找不到 `app.js` 而报「app.json 未找到」。

---

## 第 2 步：确认云环境

顶部工具栏点「云开发」图标 → 打开云开发控制台。

- 确认右上角环境名/ID 是 `cloud1-d8gdddel1d4b1cea1`。
- 若控制台提示「未开通」，说明此环境不在你账号下：退出，找负责人把环境共享给你，或在自己账号下新建环境后，修改 `config/env.js` 里三处 `cloudEnvId`（见下方「环境配置」）。

> ⚠️ 历史上出现过三个环境 ID 都是占位符（`task-dev-xxxxx` 等）导致 `Env Not Exists (-501000)` 的 bug，现已统一改为真实 ID。若你仍看到 `-501000`，检查 `config/env.js` 是否被改回占位符。

---

## 第 3 步：构建 npm（关键）

因为前端用了 `tdesign-miniprogram` 组件库，必须「构建 npm」后组件才能被识别，否则编译报 `tdesign-xxx 未找到`。

操作：顶部菜单 **工具 → 构建 npm**。

- 等待进度条完成，底部出现「npm 构建完成」或类似提示。
- 若菜单项是灰的，先确认 `miniprogram/package.json` 存在（它依赖 `tdesign-miniprogram`）。存在则点一次构建即可。

> **提示**：每次 `package.json` 改动或拉取他人代码后，建议重新「构建 npm」。若组件样式丢失，先「清缓存 → 全部清除」，再构建一次。

---

## 第 4 步：部署云函数

10 个云函数需要上传到云端才能被调用。在左侧文件树找到 `cloudfunctions/` 目录：

逐个右键每个云函数文件夹（如 `login`）→ **「上传并部署：云端安装依赖（不上传 node_modules）」**。

需要部署的 10 个：
`login`、`verifyKey`、`createTask`、`updateTask`、`getTasks`、`updateUserStatus`、`getDutySchedule`、`createLocation`、`getLocations`、`sendNotification`

- 每个上传约几秒到十几秒，底部有日志。
- 全部上传完后，在云开发控制台「云函数」列表应能看到这 10 个。

> **提示**：如果只右键了单个文件而不是文件夹，菜单里没有「上传并部署」。务必对**文件夹**右键。

> ⚠️ 不要部署 `miniprogram/cloudfunctions` 之外不存在的函数。`utils/api.js` 里的 `getReport/crawlNews/getNewsCache/exportReport` 后端尚未实现，上传会失败——这是预期的，忽略即可。

---

## 第 5 步：编译运行

回到模拟器，点工具栏「编译」（或 Ctrl+B）。

- 首页应正常渲染，点登录走通 `login` 云函数。
- 用真机扫码或在模拟器里操作：登录 → 看到任务/人员状态页面即成功。

**验证云函数是否通**：在「云开发控制台 → 云函数 → 日志」里，应能看到 `login` 的调用记录。若没有，说明环境没配对（回第 2 步）。

---

## 第 6 步：真机预览（可选但推荐）

点工具栏「预览」→ 生成二维码 → 微信扫码。真机和模拟器行为更接近，能发现订阅消息、扫码等模拟器不支持的能力问题。

> 首次真机预览需小程序已「上传代码」或在体验版。若只是自己调试，用「预览」二维码即可，无需上传。

---

## 环境配置（dev / test / prod）

`config/env.js` 根据微信的 `envVersion` 自动选环境：

| 微信环境 | 映射 | 用途 |
|----------|------|------|
| `develop`（开发者工具） | `dev` | 本地调试 |
| `trial`（体验版） | `test` | 体验测试 |
| `release`（正式版） | `prod` | 线上 |

**当前三者指向同一个真实环境** `cloud1-d8gdddel1d4b1cea1`。若你新建了独立的 test/prod 环境，把 `ENV_CONFIG` 里对应 `cloudEnvId` 改成各自 ID 即可，无需改其他代码。

## 常见问题

| 现象 | 原因 | 解决 |
|------|------|------|
| `Env Not Exists (-501000)` | 环境 ID 无效/未开通 | 检查 `config/env.js` 是否为真实 ID；确认环境已共享给你 |
| `tdesign-xxx 未找到` / 组件样式缺失 | 没构建 npm | 第 3 步「工具 → 构建 npm」 |
| `wx is not defined` / 云函数调用失败 | 云函数未部署 | 第 4 步上传 10 个云函数 |
| 登录后空白或 `users` 查询失败 | 数据库集合不存在 | 在云开发控制台「数据库」手动建 `users` 等集合（见 API 参考的[集合清单](./api-reference.md#涉及的数据库集合)），或导入负责人提供的初始化数据 |
| 订阅消息收不到 | 模板 ID 是占位符 / 未授权 | 见 [sendNotification 缺口说明](./api-reference.md#10-sendnotification-部分实现)；需申请真实模板并让用户授权 |
| 拉取他人代码后异常 | npm 没重建 | 重新「构建 npm」+ 清缓存 |
